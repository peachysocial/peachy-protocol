# The MLS store's keys and values

The layout of every record `mls/core` keeps behind `KvStore` (`mls/core/src/storage.rs`). It is this implementation's own, not part of the protocol: no other implementation reads it. The rules a store must keep (durability, rollback, erasure, one live client per unshared store) are in the specification, docs/mls-core.md §Storage layout.

Every key is:

```
schema_version (1 byte, currently 0x01) || namespace (ASCII) || 0x1F || entity_key
```

`storage_key` in `mls/core/src/storage.rs` builds every key. The namespaces OpenMLS owns key by the JSON encoding of the OpenMLS entity key and hold JSON values (`serde_json`); a list is one JSON array. The namespaces Peachy owns hold the raw bytes the table gives. The store is stamped under namespace `meta`, key `schema`. A store with a newer version is refused (`STORAGE`); an older one is re-stamped, and its old keys are not read.

Notation: `gid` is the raw group id; u16be, u32be, u64be and i64be are big-endian integers; "ms" is Unix milliseconds and "s" Unix seconds; "with the copy" means the record is deleted when the device deletes or replaces its copy of the group.

| Namespace | Key | Value |
|---|---|---|
| `meta` | `schema` | The schema version, 1 byte. |
| `group` | `gid` | `gid` again: the index of groups a reopened client lists. |
| `join_config` | JSON group id. | The group's join configuration, JSON. |
| `tree`, `group_context`, `interim_transcript_hash`, `confirmation_tag`, `group_state`, `own_leaf_index`, `own_leaf_nodes`, `queued_proposal`, `proposal_refs`, `message_secrets`, `resumption_psk`, `epoch_secrets` | JSON group id; for `queued_proposal`, the JSON pair (group id, proposal ref). | OpenMLS group state, JSON. |
| `epoch_key_pairs` | JSON group id, JSON epoch and JSON leaf index, concatenated. | Encryption key pairs, JSON. |
| `encryption_key`, `key_package`, `psk` | JSON public key, key package ref or PSK id. | OpenMLS key material, JSON, including the private halves of published key packages. |
| `signature_key` | JSON public key. | Never written; the open erases any value here (the signer is built from the device seed). |
| `account_pin` | UTF-8 actor id. | That person's current account identity key, 32 raw bytes (a value of several, sorted, reads as a set). |
| `account_pin_since` | UTF-8 actor id. | i64be: the signed `iat` of the leaf that made the current key current, never later than this device's clock when written. Absent for a pin with no time recorded, until a tree shows a leaf under it. |
| `account_known_leaves_v2` | `gid` | The leaves this conversation settled for the security-code notice while their key was the person's current one: SHA-256 over `peachy account leaf v2`, then the signature key, the HPKE key and the TLS-encoded credential, each after its u64be length, 32 bytes each, sorted. A leaf here whose key the person has since moved away from is said once, which moves it to `account_reported_leaves_v2`: after a read, no leaf is in both. Leaves no longer in the tree are dropped at each read. Absent for a conversation this core has not read. Kept when the copy is forgotten for a rejoin; dropped when the group is left for good (`forget_remembered_roster`). |
| `account_reported_leaves_v2` | `gid` | The leaves this conversation reported, or accepted at a first sight, under a key not the person's current one, in the same digest and layout. Settled for good while that key is not current: each read drops every leaf under the key current then, which `account_known_leaves_v2` keeps, and whenever a person's `account_pin` moves (in a read of another conversation, or in the pass `account_pins_dated` records), every other held or leaving conversation drops its entries for that person's leaves its tree shows under the key it moved to or the key it moved off, and every entry for a leaf no longer in its tree; for a copy forgotten for a rejoin, those keys go to `account_moved_while_forgotten`. This core writes no entry under the current key, so dropping those under the key moved off changes only a record from a store this core did not write, and only for a key move this core makes. A read first drops every entry `account_known_leaves_v2` also holds: such a leaf was settled while its key was current, so it is said once the person is, or later is, off that key. Absent until this core has read the conversation; that first read seeds it with the `account_known_leaves_v2` entries not under the current key. Kept and dropped with `account_known_leaves_v2`. |
| `account_moved_while_forgotten` | u32be group id length, the group id, the UTF-8 actor id. | The account keys that person's `account_pin` moved to or off while this copy was forgotten for a rejoin, 32 raw bytes each, sorted: written for each group id with a non-empty `account_reported_leaves_v2` that is neither held nor leaving. The copy's next read drops its `account_reported_leaves_v2` entries for that person's leaves under these keys, before judging, and then every record of this group id here. Dropped with `account_known_leaves_v2`. |
| `account_known_leaves`, `account_reported_leaves` | `gid` | The same two records in their version-1 layout, by SHA-256 over `peachy account leaf v1`, the signature key's u64be length, the signature key and the HPKE key. Read once on open, then deleted. |
| `account_pins_dated` | `done` | 1 byte, `1`: this device has dated every `account_pin` that had no `account_pin_since`, once, from every conversation it held at once, before the first notice it judged. The newest leaf any held tree shows under the pinned key, or under a key that conversation's `account_seen` holds with no `account_known_leaves_v2` and `account_retired` does not, gives the pin its key, dated by the latest leaf under that key (capped at the device clock). A pin no tree dated then is dated by the next tree that shows it. The same pass repairs a pin dated from the wrong read order: where a conversation's `account_seen` still holds several keys, the pinned one among them, and its `account_known_leaves_v2` (with no `account_reported_leaves_v2` yet) settles a leaf under a retired key of that `account_seen`, believable and issued after `account_pin_since`, that leaf's key takes the pin, dated by the latest leaf under that key, only when it is the newest believable leaf (the same `newest_believable` rule, ties to the lower key) among all such leaves and every leaf any held tree shows under the pinned key. |
| `account_seen` | u32be group id length, the group id, the UTF-8 actor id. | The account identity key(s) that group last showed as that person's current one, 32 raw bytes each, sorted. Dropped with the copy. |
| `account_retired` | UTF-8 actor id. | The account identity keys this device saw that person move away from, 32 bytes each, sorted. No reseat seats the person under one again. |
| `leaf_rotation` | `gid` | 16 bytes: i64be second the leaf was put in the tree, u64be count of messages sealed on it. |
| `opened` | u32be group id length, the group id, the first 16 bytes of the SHA-256 of an application message as it arrived. | u64be: the message's number in the group's count. Past `OPENED_KEPT` (4096) plus 512, cut to the newest 4096. Dropped with the group. |
| `opened_count` | `gid` | 16 bytes: u64be number of the next opened message, u64be lowest number still kept. Dropped with the group. |
| `peer_revoked` | A device key, 32 raw bytes. | The 64-byte signature by that device's account revoking it, then i64be second the delivery service said it took effect (0 for unknown; the earlier known time is kept). Written by `stale_leaf_removable` once verified; verified again before `process_message` refuses. Never removed. |
| `peer_heard` | `gid` | One byte, `1`: an application message from another person opened since this device's own leaf was last put in the tree. Cleared with each new own leaf; dropped with `leaf_rotation`. |
| `call_participation` | `seq` | u64be: the last call participation counter handed out. Only rises (Participant media keys). |
| `last_resort` | The raw key package ref. | i64be second it was minted. |
| `welcome_sender` | `gid` | The UTF-8 actor id whose commit seated this device. |
| `staged_commit` | `gid` | The 32-byte SHA-256 of the commit this device staged. Dropped by its merge or clear, or with the group. |
| `join_request_seen` | `SHA-256` of the group id, the proof's 16-byte nonce, its 64-byte signature. | i64be second the seat ask was signed. Dropped once the proof is too old to verify. |
| `remembered_roster` | `gid` | JSON array of `{"a": actor id, "k": [32 account-key bytes]}` (`k` absent for a leaf with none), written by `forget_group`. A person the device sees leave is removed; nobody is added. Dropped when a copy in the id is confirmed, or by `forget_remembered_roster`. |
| `epoch_mark` | `gid` | u64be. Never lowered or dropped (Welcome semantics). |
| `welcome_taken` | `SHA-256` of `peachy welcome taken v2` ‖ u64be(len) ‖ group id ‖ u64be(epoch) ‖ u64be(len) ‖ confirmed transcript hash, from the Welcome's verified GroupInfo. A record keyed by `SHA-256` of the whole Welcome is still read. | The raw `KeyPackageRef` of the last-resort package it opened. Dropped when that package is pruned. |
| `head_confirmed` | `gid` | One byte: `1` confirmed, `2` lapsed, `0` a seat no head has matched (contested when `copy_contested` is beside it). No record: made lapsed at the next open, its epoch first raised into the mark. Written by `confirm_head`, a merge of an own commit, `create_group` and every seat taken. With the copy. |
| `copy_contested` | `gid` | One byte, `1`: a head contradicted the unconfirmed copy (`head_confirmed` stays `0`). Dropped with any other head state. |
| `join_head` | `gid` | u64be epoch, 32-byte verifier: the head a seat was taken below, checked once the copy reaches that epoch. Dropped then, on confirmation, or with the copy. |
| `copy_verifiers` | `gid` | Records of u64be epoch and 32-byte verifier, oldest first, at most 65: the newest 64 epochs the copy entered, and a 65th once the copy's seat has left them. With the copy. |
| `own_commits_refused` | `gid` | u32be: own commits cleared without a merge in a row. Reset by a merge. With the copy. |
| `remembered_policy` | `gid` | The raw group state JSON `forget_group` dropped, for whether the admins changed. Dropped with `remembered_roster`. |
| `remembered_unvouched` | `gid` | As `remembered_roster`, for a copy no head ever matched. Dropped with `remembered_roster`. |
| `remembered_devices` | `gid` | JSON array of `[actor id, device id]`: every leaf's device in the copy `forget_group` dropped, for `dropped_devices`. Dropped with `remembered_roster`. |
| `rejoin_report` | `gid` | JSON array, oldest first, at most 32, of `{"by": actor id, "d": device id, "u": true, "added": [actor id, ...], "left": [actor id, ...], "adm": true, "c": true, "dd": [[actor id, device id], ...], "n": id, "t": drawn_at_ms}`. `n` is the report's id; `u`, `adm` and `c` are `readded_by_untrusted`, `admins_changed` and `contested`, absent when false; `d`, `dd`, `left` and `t` are absent when empty or unset; `by` is empty for a contested copy alone. A single object reads as a list of one, its `p` ignored. Dropped by id; all go with `forget_remembered_roster`. |
| `departed` | u32be group id length, the group id, the UTF-8 actor id. | One byte, `1`: this device saw that person's last leaf leave. Writing it removes the person from `remembered_roster`. Cleared when the person holds a leaf again, and for everyone seated in a copy before its roster is kept. Survives `forget_group`; dropped by `forget_remembered_roster`. |
| `leaving` | `gid` | u64be: the epoch this device last proposed its leave at. The group is a leaving stub, listed nowhere, until a commit removes this device (Leaving). Dropped with the group. |
| `envelope_epochs` | `gid` | Records, oldest first, of u64be epoch, one byte (always `1`, and read by nothing: kept for the layout), the 32-byte epoch envelope secret, one byte counting the device keys the commit that left that epoch added (`0xFF` when unknown, as for the current epoch) and that many 32-byte SHA-256 digests of those keys: the current epoch and the 31 before it (`ENVELOPE_PAST_EPOCHS`; The wrapped envelope). Written before each merge. With the copy. |
| `envelope_gap` | `gid` | Records of u64be epoch and 32-byte envelope secret from a reseat's gap block (The padded Welcome frame). Replaced by the next such Welcome. With the copy. |
| `held_envelopes` | Empty. | Up to 100 records, oldest first, of the mailbox kind (one byte), the receive time (u64be ms), the mailbox id (u16be length, UTF-8) and the envelope (u32be length): version 3 envelopes that opened for no group, kept once each by `hold_envelope_sealed` until released after `next_reopenable` handed them out (`release_held`) or 30 days old (A message that will not open). One whose device seal opened goes to `held_sealed` unless that hold is full (`HoldAnswer::Full`). |
| `held_sealed` | The 32-byte SHA-256 of the envelope. | Version byte `1`, mailbox kind (one byte), receive time (u64be ms), envelope length (u32be), the message's epoch (u64be), urgency (one byte: `0` waiting, `1` due at the budget or the 30 days, `2` urgent near the ceiling), handed out before (one byte), the 32-byte envelope secret, the sender's 32-byte device key, the group id (one-byte length), the UTF-8 mailbox id (the device seal, not part of this specification). At most 1,000, or 64 MiB of envelopes. Deleted with its `held_body` by `release_held` or when dropped. |
| `held_body` | The 32-byte SHA-256 of the envelope. | The envelope's bytes. |
| `held_released` | The 32-byte SHA-256 of the envelope. | Release time (u64be ms): a `held_sealed` envelope released, never held again. A seal dropped, or refused as not its message's author's, writes none. Kept 30 days, at most 4,096, oldest first out; pruned at a client's first pass and hourly. |
| `leaf_people` | `gid` | Version byte `1` (any other does not read), when the copy was let go (u64be ms, `0` while held), then per device key a leaf of the copy held: the 32-byte key, the epoch the copy first held no leaf with it (u64be, `0` while it does), when this device saw that (u64be ms, `0` while it holds one), and the actor id (one-byte length, UTF-8) from a credential that checked. A time ahead of the clock is set to the clock's reading when next read. At most 2,048 keys a group, longest gone first. Dropped 30 days after the copy is let go, never kept for one let go at epoch 0, and dropped at once on a leave on purpose (`forget_remembered_roster`, and the end of the leave). Names the sender of a sealed envelope whose device has left the tree. |
| `opened_content` | UTF-8 mailbox envelope id, a zero byte, the message's 16-byte digest. | Version byte `1`, u64be ms kept, the group id (u16be length), the 16-byte digest the `opened` record uses, the sender (actor id and device id, each with a u16be length; the 32-byte device key; the kid with a u16 length; i64be expiry and issue seconds; one byte `1` and the 32-byte account key, or `0`), the plaintext. Written by `process_message_as`; dropped by `release_opened`, or once 30 days old or past the newest 1000. |
| `carried_leave` | u32be group id length, the group id, the raw proposal reference. | u64be epoch, then the leave proposal message as it arrived (The carried commit). Current epoch only; dropped with the group. |
| `head_vouched` | `gid` | u64be: the highest epoch of the copy the group's own head vouched for. Only raised. With the copy. |
| `head_read` | `gid` | u64be ms: when this device last finished reading the group's head. With the copy. |
| `steward_keys` | `gid` | Records, oldest first, of u64be epoch, u64be s written and the 32-byte steward key the meta named at each epoch the copy entered. Records past `STEWARD_KEY_KEPT_SECONDS` go when one is written. |
| `group_hold` | `gid` | The group's hold as JSON (not part of this specification), kept after it lapses until the copy leaves its epoch. |
| `stamp_steward` | `gid` | The 32-byte steward key the sealed stamp of the last merged commit named; absent for none. |
| `stamps_opened` | `gid` | One byte: `0` every stamp opened since the seat named no steward, `1` one did. Absent: none opened. With the copy. |
| `counted_steward` | `gid` | The steward key the group counts (32 bytes, or empty for none) while a commit by somebody who may not change it rewrote the meta's. |
| `hold_started` | `gid` | u64be s: when the group's last full hold began. Survives `forget_group`; dropped when the person leaves the group. |
| `hold_repeats` | `gid` | u32be: repeat holds since that full hold. As `hold_started`. |
| `hold_rejoined` | `gid` | One byte, `1`: a copy was forgotten while a hold was on record since that full hold. Dropped by the next full hold. |
| `own_install_link` | UTF-8 device id of a linked row. | The UTF-8 id of the row it names as its twin, as the account's device list first stated it. First sight wins. |
| `restore_snapshot` | u64be `restored_since`. | JSON array of the hex device keys that restore signed out, as its answer named them and their certificates verified. First write wins. |
| `own_key_signed_out` | The 32-byte device key. | Empty: a key this device signed the revocation of, or took from a restore's answer as signed out. Never approved again. |
| `remembered_own_devices` | `gid` | Not used; deleted with `remembered_roster` where present. |
| `own_approver` | UTF-8 device id. | The 32-byte signing key of the own device that let this one in (`remember_own_approver`). Dropped by `forget_own_device`. |
| `own_sibling_key` | UTF-8 device id. | The 32-byte device key held for that own device: bare when taken from a tree, or followed by the evidence byte `1` when taken from a verified approval or this device's own add. Evidence replaces a key from a tree; nothing else overwrites. Never dropped. |
| `own_forgotten` | UTF-8 device id. | One byte, `1`: an own device forgotten as removed (`forget_own_device`). Never dropped; device ids are not reused. |
| `own_forgotten_key` | The 32-byte device key. | The UTF-8 device id it was forgotten under: a key a forgotten device was seen holding, or the device list gave for it. Counts for nothing under any id. Never dropped. |
| `own_seat_vouched` | The device's 32-byte signing key, then the UTF-8 device id. | One byte, `1`: `check_own_device_approval` answered a verdict that seats this own device. |
| `own_vouched` | The device's 32-byte signing key, then the UTF-8 device id. | The 32-byte signing keys of the approvers whose approval of that device verified, concatenated, or the one byte `1`, naming no approver, which the core never writes and replaces when it records an approval. Written only by `check_own_device_approval` answering `approved` (What the adder checks). |
| `own_unvouched` | The device's 32-byte signing key, then the UTF-8 device id. | One byte, `1`: a leaf of this account added by a member this device did not count as its own. Dropped when an approval for it verifies. |
